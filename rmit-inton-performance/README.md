# RMIT INTON Paid Performance

- Purpose and owning team or GitHub handle: RMIT International (INTON) paid social performance across Meta and TikTok: monthly spend, delivery, campaign type, objective, ad sets / ad groups and creatives by market. Owner: @stephanieligms-max (GMS).
- Published route: https://spark.kmt.global/rmit-inton-performance/
- Canonical editable source and how authorised contributors obtain access: a private local source project maintained by the owner; it is not in this repository. Ask the owner for access. Do not edit `index.html` here by hand.
- Maintenance mode: compiled static export. `index.html` is generated by the source project's public build and copied here with its `assets/`.
- Runtime and build prerequisites; exact build/export command and base path: the public build runs in the private source project (Python 3.9+) and writes a single static `index.html` that uses relative `assets/` paths, so it works under `/rmit-inton-performance/` with no base-path setting. No build step runs in this repository.
- Local preview command and test URL: from the repository root, `python3 -m http.server 8000 --bind 127.0.0.1`, then open http://127.0.0.1:8000/rmit-inton-performance/
- Tests and dependency/security audit commands: the repository checks in [CONTRIBUTING.md](../CONTRIBUTING.md). The source project also renders the page in headless Chrome and checks totals, layout and a public profile (no internal IDs, budgets, recommendations, person names, internal file names or paths) before each export. The page has no third-party scripts or npm dependencies.
- Configuration names and secret references (never values): none. The page has no API keys or backend. The shared password is kept by the owner and is never committed; the page contains only a salted PBKDF2 verifier.
- Public-data suitability and authentication/backend boundaries: the data in this page is public. It holds aggregated campaign, ad set and ad names with spend and delivery metrics; internal platform IDs are replaced by opaque keys, budgets and recommendations are left out, and person names in ad names are replaced by neutral labels. The password screen is a client-side gate only, in the same style as `pr-dashboard/`: it is not access control, and anyone can read the data in the page source or this repository. `noindex, nofollow` only discourages indexing.
- Release/export steps, assets to retain and recovery procedure: one PR per refresh that replaces `index.html` (and `assets/` only when they change), following the delivery flow in [CONTRIBUTING.md](../CONTRIBUTING.md). Keep `assets/` (GMS and KMT logos, DM Sans font and its OFL licence). Recovery: revert the release PR on a new branch and merge the revert through a PR.
- Known limitations or external services needed for verification: data is a point-in-time snapshot ("Data through" date on the page); the current month is month to date. TikTok landing page views are TikTok conversions and include view-through attribution. The remembered-device option stores only an expiry marker in the browser.
